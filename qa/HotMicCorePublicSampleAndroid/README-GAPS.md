# README gaps — HotMicCore Android, as met while building this sample from README.md + MIGRATION.md only

Numbered like the iOS `README-GAPS.md` so the two lists can be compared. "Cost" = what it cost an outside
developer (or would cost) to find out. Verified against the SDK behaviour observed in the QA rows (`Nxx`).

| # | Gap | Cost | Proposed README text / change |
| --- | --- | --- | --- |
| 1 | **Base URL / environment** — nothing says which backend the SDK talks to or that it cannot be changed (`baseUrl` is `internal`). | Medium: a staging tenant on prod is the only option; an integrator with a staging API has no way to point Core at it. | "Core talks to `https://api.hotmic.io`; there is no staging switch. Use a staging *tenant* (API key) on the production API." |
| 2 | **Coroutines dependency** — the README says "Kotlin 2.1+ with `kotlinx.coroutines`" but the Installation block does not add `kotlinx-coroutines-android`; Core's own dependency is `implementation`, so `lifecycleScope`/`Dispatchers.Main` etc. are not on the host's classpath. | Low (build error names the class). | Add `implementation("org.jetbrains.kotlinx:kotlinx-coroutines-android:1.9.0")` to the Installation block. |
| 3 | **Polling cadence and duplicates** — events arrive from a 3 s poll (`ChatBatchReceived` ≈ 3–6 s after send, N9 p50 4.0 s); messages, deletes and reactions may be delivered **twice** (N9: 12 of 20), so hosts must key chat state by `id`. | High: a naïve `list += batch.messages` shows duplicates. | "Poll every 3 s (server-configured). Key chat by `HotMicChatMessage.id`; the same event may be delivered more than once." (Fixed on `hem-96-fixes`; keep the advice.) |
| 4 | **What an invalid token does** — with an expired/malformed/empty/wrong-secret JWT `fetchStreams` throws `Unauthorized` but `fetchStream`, `fetchUser` and `session.start()` **succeed** as an anonymous guest (`Guest…`, `userRestrictions = view_and_polls_only`), and chat then throws `Unauthorized` (N15). A token that expires mid-session gives no event at all (N15MID, F4). | High: an app can "work" with a broken token and only fail at first chat. | Document the guest fallback and the restriction value; after `hem-96-fixes`: "when the token is rejected mid-session the session moves to `Failed(Unauthorized)`; create a new client and session". |
| 5 | **Java / callback callers** — every call is `suspend`; there are no callback or `Future` overloads (iOS has completion handlers). `eventListener` is the only non-Flow surface. | Medium for Java hosts. | State it in Requirements: "Kotlin coroutines are required; Java callers need a small coroutine bridge." |
| 6 | **`events` buffer** — `events` is a `SharedFlow(extraBufferCapacity = 64)` emitted with `tryEmit`: a slow collector loses events silently. | Medium. | "Collect `events` promptly; more than 64 undelivered events are dropped. Use `eventListener` for synchronous delivery." |
| 7 | **Own actions are not echoed — including deletions by others** — the README says sends/deletes/reactions are not delivered through events; it does not say the *author* also never learns when a moderator deletes their message (N9/F3). | Medium. | After `hem-96-fixes`: "Your own sends/deletes/reactions are not echoed; deletions by others *are*." |
| 8 | **Playback URLs in list rows are null** — `fetchStreams` rows have `hlsUrl`/`vodUrl` = null (`GET /streams` omits them); only `fetchStream(id)` and the session snapshot populate them (N5, iOS F12). | Medium: a list-driven player gets nothing. | "Use `fetchStream(id)` or the session's `HotMicStream` for playback URLs; list summaries do not carry them." |
| 9 | **Error mapping is backend-driven** — auth failures come back as `Server(500, "App not found")`, `Server(500, "WARN: addModerator not authorized")`, `Server(500, "User not found")`, `Server(400, null)`; `Forbidden` is never produced; `Decoding` is never thrown to callers (N15/N12/N23). | Medium. | Note next to the error table which codes the backend actually returns for wrong key / not authorised, and that `Forbidden` is reserved. |
| 10 | **Filter and paging do not work end-to-end** — `includesLive/Scheduled/VOD` and `page` have no effect after the first call with the same `limit` (CDN caches `GET /streams` by `limit` + `user_id` only, N4/F5). | High for any list UI. | Backend fix; until then "vary `limit` per filter combination" is the only workaround — say so or fix the cache key. |
| 11 | **Background / Doze / offline behaviour** — nothing says what happens to a session in the background. Observed (N13, baseline): polling silently stalls under Doze with no `Reconnecting`, and **every chat message sent while backgrounded is lost** on return (the backend serves a ~6 s window; the SDK skips to now). | High. | Document expected behaviour; after `hem-96-fixes` the session catches up on return (≤ 5 min). Recommend `stop()` in `onStop` for chat-critical hosts or note the catch-up limit. |
| 12 | **`stop()` and `Disconnected`** — `ConnectionChanged(Disconnected)` is only ever emitted by `stop()` on the shipped SDK; a dead network gives `Reconnecting(n)` forever (N14/F1). | Medium. | After `hem-96-fixes`: "`Disconnected` after 20 consecutive failed polls; retries back off to 60 s; `Connected` on recovery." |
| 13 | **`logLevel` does nothing** — "To enable diagnostics, pass a `logLevel`" — the shipped SDK emits no log line at any level (N3). | Low–medium (debugging blind). | Fixed on `hem-96-fixes` (tag `HotMicCore`); README should name the logcat tag. |
| 14 | **Release/R8** — "Core ships consumer ProGuard/R8 rules" is true; the sample's release build (`isMinifyEnabled = true`) needs no extra rules (N3). | None. | — |
| 15 | **Session lifetime without `stop()`** — an active session that is simply dropped keeps polling until the process dies (N17); iOS deallocates it. | Medium (battery/network leak in careless hosts). | "Always call `stop()`; a dropped session keeps its network work alive." |
| 16 | **Value-class raw values** — `HotMicStream.State` etc. are `value class`es; an unknown server value produces e.g. `State("PAUSED")`, so `when` on the companion constants needs an `else`. | Low. | One sentence under Media Playback. |
| 17 | **Token rotation** — "Create a new `HotMicClient` when the access token changes" but an *active* session cannot take a new token; rotation = `stop()` → new client → new session (N16). | Medium. | Say it explicitly. |
| 18 | **Presence/participants cadence** — `ParticipantsUpdated` for a new viewer arrives up to 120 s later (viewers refresh 120 s, presence 60 s; N11). | Low–medium (looks broken in a demo). | State the cadence. |
| 19 | **`PollUpdated` on start** — every session start re-emits `PollUpdated` for polls the user has already answered (N6). | Low. | "Treat `PollUpdated` as idempotent." |
| 20 | **`HotMicClient(context)` vs no-context** — README says "pass an application Context so requests carry a stable device identifier". It does not say the device id drives the "own message" filter: two sessions with the same user on the same device never see each other's chat; two devices with the same user do. | Low. | One sentence. |
| 21 | **Version / SNAPSHOT** — README installs `0.1.0-SNAPSHOT` from `mavenLocal()`; there is no released version and no GitHub Packages coordinates yet (checklist covers this). | Blocking for a public repo. | Rewrite the Installation section for the published coordinates + token requirement (see `evidence/android-go-public-checklist.md`). |
| 22 | **Empty chat accepted** — `sendChatMessage("")` returns 200 (N8/F10); `"   "` → `Server(400)`. | Low. | Backend; note or validate client-side. |
| 23 | **Example needs `local.properties`** — the shipped Example's `sdk.dir` and the optional creds prefill are documented; the sample followed it fine. | None. | — |
| 24 | **`StreamEnded` on VOD** — the first poll of every VOD session emits `StreamEnded` (backend `end_video=true` for replays). The README says "transition to your end-of-stream experience"; a host that does so on a replay stops playback at once (this sample did, N7). | High for replay UIs. | "`StreamEnded` is also delivered for VOD streams (the broadcast has ended); only treat it as terminal when `stream.state == Live`." |
